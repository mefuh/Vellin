# Сквозные проверки звонков

Два человека — два отдельных браузера Chrome со своими «микрофонами» —
звонят друг другу через сайт, а тесты проверяют то, что эти люди слышат и
видят. Устройство приложения тестам неизвестно: они пользуются только тем,
что доступно человеку (кнопки, подписи, адреса страниц), публичным API
(регистрация, дружба, создание комнаты) и стандартными API браузера.

## Как устроена проверка «слышат друг друга»

- В микрофон каждого Chrome подаётся своя речь: синтезатор Windows (русский
  и английский дикторы), без него — синтетическая речь с разной высотой.
- Зонд на странице меряет уровень звука только у того, что реально играет:
  медиаэлементы не на паузе, не заглушены, с живой звуковой дорожкой. Свой
  голос приложение глушит — зонд его не слышит, как не слышало бы ухо.
- «Слышит» — речь в заметной доле замеров (обычно 60–80 %, около −30 дБ).
  «Тишина» — около −110 дБ и ни одного замера с речью.
- Что звук идёт именно от собеседника, доказывается причинно: его микрофон
  выключен кнопкой — у второго тишина, включён — речь вернулась.

## Запуск

Нужен поднятый стенд: база и `npm run dev` (сайт на https://localhost:5173,
сервер на :3001). Затем из корня репозитория:

```bash
npm run test:e2e                     # все проверки
npm run test:calls                   # только личные звонки
CALL_SOAK_SEC=600 npm run test:calls # стабильность — 10 минут разговора
HEADED=1 npm run test:e2e            # с окнами браузеров
E2E_VERBOSE=1 npm run test:e2e       # уровни звука в каждой проверке
```

Переменные: `VELLIN_SITE`, `VELLIN_API` — адреса стенда; `CALL_SOAK_SEC` —
длительность долгого разговора (по умолчанию 60 с); `E2E_BROWSER_CHANNEL` —
канал Chrome (по умолчанию установленный `chrome`).

Каждая проверка создаёт свою пару людей; после прогона они удаляются из
базы стенда. Отчёт — `e2e/report`, следы упавших проверок — `e2e/results`.

## Что проверяется

- вызов доходит, принимается, отклоняется, отменяется;
- оба слышат друг друга; звук идёт от собеседника; нет эха своего голоса;
- разговор держится без провалов звука (по умолчанию 60 с);
- шесть звонков подряд в обе стороны — каждый соединяется;
- обрыв связи с сервером на 8 с — голос не прерывается, звонок живёт;
- перезагрузка страницы — звонок восстанавливается со звуком;
- свернуть звонок, перейти по сайту — звук не прерывается;
- камера и демонстрация экрана доходят и не мешают звуку; выключенные
  камера и демонстрация действительно освобождают устройства;
- после отбоя звук пропадает, а микрофон и камера освобождены;
- звонок с телефона; голосовой чат в комнате.

## Сайт ↔ клиент для Windows

`tests/app-call.spec.ts` звонит из Chrome в настоящий клиент для Windows.
Клиентом управляет `winapp/integration_test/remote_person_test.dart`: он
запускает приложение и снаружи видит только то, что на экране (тексты и
подписи кнопок), а действия выполняет как человек — нажатием по подписи и
вводом в поле.

- Микрофон у клиента — настоящий, машины, и может молчать. Поэтому что голос
  идёт в обе стороны, проверяется по сети со стороны сайта: пакеты голоса из
  приложения приходят, а приложение присылает отчёты о приёме нашего голоса.
- Сторона, уступающая при встречном согласовании соединения, задаётся
  порядком регистрации, и каждая проверка идёт в обеих раскладках.
- Клиент хранит вход в общем файле настроек
  (`%APPDATA%\ru.vellin\vellin_winapp\shared_preferences.json`). Перед
  запуском он копируется и после прогона возвращается на место — и при
  падении тоже, — чтобы не затереть сессию установленного приложения.
- Нужны Windows и Flutter (`FLUTTER` — путь к `flutter.bat`, по умолчанию
  `C:\src\flutter\bin\flutter.bat`). Пропустить: `SKIP_APP_TESTS=1`.

Звонки приложение ↔ приложение этими тестами не проверяются: две копии
клиента пишут вход в один и тот же файл настроек и одновременно не живут.
